# Phase 4.5 归档报告 — SHELL_PATTERNS 单管道 `|` 注入拦截修复

**日期**: 2026-05-19

**范围**: 仅限 `local_api/validators.py` 一行修改

---

## 1. 修改目标

修复 4.3 预存问题：`SHELL_PATTERNS` 未拦截单管道符 `|`，导致 `TestShellInjection::test_pipe_rejected` 失败。

**测试用例**：发送 `{"title": "cat /etc/passwd | mail"}` 到 `POST /api/tasks`，期望返回 **422**（shell 注入拦截），实际返回 **201**（创建成功，未被拦截）。

---

## 2. 根因

`local_api/validators.py` 第 38–54 行的 `SHELL_PATTERNS` 列表包含双管道 `||`（逻辑或）的匹配正则，但**缺少匹配单管道符 `|`（管道操作符）** 的正则。

```
SHELL_PATTERNS 现有模式（简化）:
  ;           ← 分号 ✅
  &&          ← 逻辑与 ✅
  ||          ← 逻辑或 ✅（双管道）
  |           ← 单管道 ❌ 缺失 ← 本次修复
  `           ← 反引号 ✅
  $( )        ← 命令替换 ✅
  ${ }        ← 变量扩展 ✅
  ...
```

**验证链路**：
```
POST /api/tasks {title: "cat /etc/passwd | mail"}
  → middleware.py:117  deep_check_body(body)
    → validators.py:82  check_shell_injection(value)
      → for pattern in SHELL_PATTERNS: pattern.search(value)
        → 所有 pattern 均未命中（无 | 匹配项）
        → return None → 放行
  → 201 Created ❌ 应为 422
```

## 4. 实际修改内容

```python
# 修改前（第 38–42 行）：

    re.compile(r";"),

    re.compile(r"\|"),          # ← 新增：匹配单管道符（管道操作符）
    re.compile(r"`"),
```

- 源码实际内容：`re.compile(r"\|")`
- 位置：第 42 行，`\|\|` 之后、`` ` `` 之前（管道相关模式保持相邻）

## 7. 管道符 `|` 渲染说明

本报告中所有 shell 管道符均指 ASCII 字符 `|`（U+007C，Vertical Bar）。如在终端或复制渲染中出现 `\`、`|` 等效显示变异，属格式化/转义渲染问题，不代表源码内容。

**源码确认**：`local_api/validators.py` 第 42 行实际内容为：

```python
re.compile(r"\|")
```

其中 `\|` 在正则表达式中表示匹配字面管道符 `|`。
